# 专家观点 04：行为设计专家

**专家身份**：行为设计（Behavioral Design）与用户体验专家，专注于习惯形成类产品的设计，具有将心理学理论转化为数字化产品交互的丰富经验。

---

## 一、习惯形成的核心模型

### 1.1 习惯回路（Habit Loop）

Charles Duhigg (2012) 和 James Clear (2018) 提出的一致模型：

```
提示 (Cue) → 渴望 (Craving) → 回应 (Response) → 奖励 (Reward)
```

**对吸烟/饮酒习惯的分析**：

| 环节 | 吸烟 | 饮酒 |
|------|------|------|
| **提示** | 饭后、压力、咖啡、看到别人抽烟 | 饭桌、社交、下班后、情绪低落 |
| **渴望** | 尼古丁的放松感、手口动作的熟悉感 | 微醺的放松感、社交融入感、"养生"信念 |
| **回应** | 点烟、吸烟 | 倒酒、喝酒 |
| **奖励** | 尼古丁刺激多巴胺释放、深呼吸的平静 | 酒精抑制前额叶产生放松感、"活血"的身体错觉 |

**产品设计目标**：保留旧习惯的"提示-奖励"结构，但替换中间的"回应"行为。

### 1.2 福格行为模型（Fogg Behavior Model）

BJ Fogg (2009) 提出：**行为 = 动机 × 能力 × 触发**

| 要素 | 含义 | 对产品的挑战 | 解决策略 |
|------|------|-------------|----------|
| **动机 (Motivation)** | 想做某事的意愿 | 目标用户动机极低 | 利用健康计算器唤起好奇，利用损失厌恶 |
| **能力 (Ability)** | 完成某事的难度 | 必须极简单 | 3步内完成核心动作，无需登录 |
| **触发 (Trigger)** | 提醒行动的信号 | 用户不会主动想起 | 家人可以设置提醒；每日首次打开有推送式内容 |

**产品核心方程**：
```
打开产品的行为 = 好奇心（动机）× 一键可达（能力）× 家人发链接（触发）
```

### 1.3 Hook 模型（上瘾模型）

Nir Eyal (2014) 的 Hook 模型描述了习惯形成类产品的设计框架：

```
触发 (Trigger) → 行动 (Action) → 可变奖励 (Variable Reward) → 投入 (Investment)
```

**产品应用**：

| 阶段 | 设计实现 |
|------|----------|
| **外部触发** | 家人分享链接；每日一条科学卡片（生成可分享图片） |
| **内部触发** | 焦虑/压力时想到"看看我坚持了几天"；饭后习惯性想抽烟时→想到打卡 |
| **行动** | 最简操作：1次点击 = 完成打卡；1次点击 = 查看今日科学卡片 |
| **可变奖励** | 每天的科学卡片内容不同（新鲜感）；身体恢复数据逐步变化（期待感） |
| **投入** | 打卡天数越多，越不想"断链"；累计数据价值越高，用户粘性越强 |

## 二、具体交互设计方案

### 2.1 入口设计：如何"欺骗"大脑打开页面

**原则**：降低威胁感，提高好奇心

**方案 A：健康计算器（推荐为主入口）**
```
┌────────────────────────────────┐
│  你的身体"真实年龄"是几岁？    │
│                                │
│  输入每天吸烟量：____支       │
│  输入每天饮酒量：____两       │
│  年龄：____岁                 │
│                                │
│  [开始计算 →]                 │
│                                │
│  *不收集任何数据，仅本地计算   │
└────────────────────────────────┘
```

设计要点：
- 标题使用"身体年龄"而非"健康检测"——前者更中性有趣
- 副标题强调隐私（本地计算）→ 降低戒心
- 按钮文案用"开始计算"而非"开始评估"——计算是中性行为，评估含评判意味

**方案 B：好奇心卡片（次入口/每日推荐）**
```
┌────────────────────────────────┐
│  😮 99%的人都不知道：          │
│                                │
│  每天喝二两白酒 = 每年多摄入    │
│  相当于XX块方糖的热量          │
│                                │
│  [查看更多真相 →]              │
└────────────────────────────────┘
```

### 2.2 打卡机制设计

**原则**：正向强化、不评判、低压力

```
┌────────────────────────────────┐
│  📅 第 7 天                    │
│                                │
│  🟢🟢🟢🟢🟢🟢🟡            │
│  一  二  三  四  五  六  日    │
│                                │
│  今天：                        │
│  [✓ 没抽烟]                    │
│  [✓ 没喝酒]                    │
│  [○ 少喝了（比昨天少___杯）]   │
│                                │
│  累计省钱：¥1,050              │
│  相当于：给孙女买了3件新衣服    │
└────────────────────────────────┘
```

关键设计决策：
- **不设"失败"状态**：忘记打卡 = 灰色圆圈，不是红色叉号
- **"部分成功"选项**："今天少喝了"也是胜利
- **金钱的具体化**：把累计省钱映射到用户在乎的东西上（给孙女买衣服 > 抽象的"省钱了"）

### 2.3 身体恢复时间线设计

**原则**：利用即时反馈维持动机

```
┌────────────────────────────────┐
│  📊 你的身体正在恢复           │
│                                │
│  已戒 7 天：                    │
│  ✅ 20分钟：心率恢复正常        │
│  ✅ 12小时：血氧含量改善        │
│  ✅ 2-3天：味觉嗅觉提升        │
│  🔄 2周：肺功能开始改善        │
│  📅 1年：心脏病风险降低50%     │
│                                │
│  下一个里程碑：3天后的"2周"     │
└────────────────────────────────┘
```

设计要点：
- 已完成项用✅标记（正向强化）
- 当前进行中项用🔄标记（期待感）
- 未来项标记时间（"3天后"）→ 形成期待
- 每一个里程碑都是一个"可变奖励"

### 2.4 谣言粉碎机设计

**原则**：先认同、后呈现、不做裁判

```
┌────────────────────────────────┐
│  常见说法 vs 科学事实          │
│                                │
│  ┌─────────────────────────┐  │
│  │ "每天一杯酒活血化瘀"     │  │
│  ├─────────────────────────┤  │
│  │ 事实：酒精确实能暂时    │  │
│  │ 扩张血管，但长期饮用    │  │
│  │ 会导致血压升高，增加    │  │
│  │ 心脑血管疾病风险        │  │
│  │                         │  │
│  │ 来源：WHO, Lancet 2023  │  │
│  └─────────────────────────┘  │
│                                │
│  ← 上一则  下一则 →            │
└────────────────────────────────┘
```

交互要点：
- 左右滑动浏览，像卡片一样轻量
- 每个卡片一个"说法"→ 避免过量信息
- 科学事实部分用不同背景色区分
- 来源清晰可查

## 三、数字助推（Digital Nudge）的具体设计

**原则**：不强制、不限制选择、引导而非控制

### 3.1 默认选项（Defaults）

Thaler & Sunstein (2008) 指出，默认选项极大地影响选择结果。

- 打卡页面的默认状态是"已记录"而非"未记录"
- "今天的目标"默认显示"和昨天一样"而非空白（维持现状偏误 + 承诺一致）

### 3.2 社会规范（Social Norms）

- "和你同龄的人中，XX%已经意识到过量饮酒的危害"（描述性规范）
- "这个社区里，很多人都在为家人戒烟戒酒"（代言性规范）

### 3.3 选择架构（Choice Architecture）

- 合理安排选项顺序：健康选项放在前面
- 减少选择数量：每次只提供一个"行动建议"
- 预承诺机制："预约"明天的打卡，增强承诺

### 3.4 反馈时机（Feedback Timing）

- 立即反馈 > 延迟反馈
- 每次打卡后立即显示"恭喜！你又坚持了一天"
- "你刚刚省下了XX元"（精确到每次点击）
