# 新生 — 行为改变产品设计文档

## 产品哲学

这个产品不是为了"告诉用户该怎么做"，而是为了**在用户最需要的时候出现在他身边**。

我们不做：
- 健康计算器（v1 教训）
- 一次性情感冲击（v2 教训）  
- 每日一次洞察对话（v3 教训——洞察有，但不在关键时刻起作用）

我们做：
- **全天持续陪伴**：一天 4 次微干预（30 秒 × 4 = 2 分钟/天）
- **渴求瞬间救援**：一键打开的紧急干预
- **洞察 × 行动**：对话产生动机，通知在关键时刻唤起执行

## 当前产品架构（v4）

```
xinsheng/
├── index.html        (1.4KB) 入口 → 注册 SW → 跳转 app.html
├── app.html          (46KB)  完整 SPA（CSS+storage+engine+protocol 全内联）
├── sw.js             (2.4KB) Service Worker（缓存+通知+后台同步）
├── manifest.json     (0.4KB) PWA 清单（可添加到主屏幕）
└── icon.svg          (0.5KB) PWA 图标
```

## 核心功能

### 1. 微干预日间节奏
| 时段 | 模块 | 时长 | 触发 |
|------|------|------|------|
| 07:00 | 🌅 早间计划 | 30秒 | 通知 + 打开页面 |
| 12:00 | ☀️ 午间检查 | 15秒 | 通知 |
| 17:00 | ⚠️ 高危提醒 | 20秒 | 通知 |
| 21:00 | 🌙 晚间反思 | 45秒 | 通知 |

### 2. 紧急渴求救援（#emergency）
- **主屏幕一键打开**：直接进入救援模式
- 4 种场景：🚬想抽烟 / 🍺想喝酒 / 📱想刷手机 / 😤心情很差
- 每种场景有 2-4 步结构化干预（深呼吸 → 替代行为 → 家人介入）
- 设计原则：15 秒内开始执行，而非继续思考

### 3. PWA 能力
- 离线可用（service worker 缓存 app shell）
- 可添加到主屏幕（manifest + install prompt）
- 系统通知推送（4 次/天，时间段感知）
- 安装后行为类似原生应用（全屏、无地址栏）

### 4. 21天对话协议（保留内容）
S0 价值观探索 → S1 触发觉察 → S2 执行意向 → 第3-21天每日微干预

## 技术实现说明

### 通知系统（纯前端，无需服务器）
用 `setTimeout` 链 + Service Worker `showNotification()` 实现：
- 用户打开页面时注册当天 4 个时间点的通知
- 即使页面在后台标签页，通知也能正常触发
- 对于已安装 PWA 用户：可通过 Periodic Background Sync 在浏览器关闭时唤醒

### 紧急模式路由
URL hash 控制视图：`app.html#emergency` 直接进入救援模式
主屏幕图标可直接指向紧急模式

### 约束
- 纯静态站点（GitHub Pages）→ 无服务端
- 无需登录、无后端 API、无数据库
- LocalStorage 存储全部用户数据

## 已验证的证据基础

| 来源 | 关键发现 |
|------|---------|
| Nature Human Behaviour 2025 (152 RCTs) | 个性化数字干预 RR 1.86，短信干预最有效 RR 1.63 |
| Xu & Smit 2023 JITAI 元分析 | 及时适应性干预效果量 g=0.77 |
| Gollwitzer & Sheeran 2006 元分析 | 实施意图 d=0.65 |
| Quit Sense (UEA, 2024) | 情境感知戒烟应用：12% vs 3% 戒断率 |

## 未来方向

1. **超个性化通知**：根据用户设定的 values（family/health/dignity/child）定制每条通知
2. **社交连接**：允许用户预设一个"监督人"，在渴求时一键发送求助短信
3. **真实世界触发记录**：用户标记"刚才在哪里想抽烟"，形成个性化高危地图
4. **多语言**：扩展支持英文/方言
5. **微随机试验**：通过 A/B 测试不同通知文案的效果
