# 根本缺陷分析与系统改进方案

## 一、根本问题：意图-行为鸿沟

当前产品能制造"洞察时刻"——用户在对话中被触动、被理解、产生了改变的意图。但问题是：

**意图 ≠ 行动。**

用户反馈完美地描述了这个问题：
> "这一刻我感觉到了，我需要这么做，我理解了。这一刻触动了我，下一刻忘掉了。然后这一天没有任何触发，再跟往常一样。"

这是心理学中最经典的 Intention-Behavior Gap。元分析数据显示：
- 意图到行动的转化率仅约 50%（Sheeran, 2002）
- 实施意图（implementation intentions）对目标达成的效果量为 d=0.65（Gollwitzer & Sheeran, 2006）
- 但对戒烟的 effect size **显著较小**——因为"不做什么"比"做什么"更难自动化

## 二、证据基础

### 2.1 什么有效？

| 干预类型 | 效果量/RR | 证据来源 |
|---------|-----------|---------|
| 个性化数字干预 | RR 1.86 | Li et al. Nature Human Behaviour 2025 (152 RCTs) |
| 短信干预 | RR 1.63 | 同上 |
| JITAI 行为改变 | g=0.77 | Xu & Smit meta-analysis 2023 |
| 实施意图 | d=0.65 | Gollwitzer & Sheeran 2006 |
| 应用+药物联合 | OR 1.79 | Guo et al. JMIR 2023 |
| 纯应用单独 | OR 1.25 (n.s.) | 同上 |

**关键发现**：纯应用单独使用**不显著**。但个性化+多组件的组合干预有效。

### 2.2 现有产品的失败原因

Quit Sense (UEA, UK) 是目前最接近正确的产品——它使用手机传感器（GPS、加速计）检测高风险地点，在用户进入这些地点时发送实时支持。可行性 RCT 显示 12% vs 3%（6个月戒断率）。

但大多数戒烟应用的问题（基于 228 个应用的评估）：
- 31% 在一年内停止运行
- 缺乏循证支持（只有 12 个应用有发表研究支持）
- 纯自助无个性化
- **不支持触发瞬间干预**

## 三、系统改进方案

### 约束条件
- 纯静态站点（GitHub Pages）
- 父亲的使用场景（非技术人员、手机浏览器）
- 必须零服务端依赖

### 3.1 核心架构改变：从"会话"到"持续在场"

**当前模型**：
```
用户打开页面 → 对话（5-15分钟）→ 关闭 → 直到明天
```

**目标模型**：
```
用户打开页面 → 30秒微干预 → 关闭 → 白天通过 PWA 收到 2-3 次外触发
                                                           ↓
                                             回到页面 → 情境感知的即时支持
```

### 3.2 多时间尺度干预

```
时间→  早晨             中午               傍晚              睡前
     ┌────────┐    ┌────────┐    ┌────────┐    ┌────────┐
     │ 日间计划 │    │ 触发检查 │    │ 高危时段 │    │ 晚间总结 │
     │ 1-2分钟  │    │ <1分钟  │    │ 即时干预 │    │ 1-2分钟  │
     └────────┘    └────────┘    └────────┘    └────────┘
```

### 3.3 技术实现方案（全静态可行）

#### A. Service Worker + 通知推送
- 注册 Service Worker，实现全离线可用
- 使用 Push API + VAPID 推送通知（免费浏览器推送服务）
- 当用户进入高危时间段（如饭后、下班后），发送通知：
  - "还记得你的计划吗？饭后嚼口香糖替代抽烟。"
  - "深呼吸3次。然后再决定。"

#### B. "紧急按钮"功能
- 推荐用户将页面添加到主屏幕（PWA）
- 主屏幕图标在渴求发作时快速打开
- 打开直接显示：**"现在感觉怎么样？"** 加上 3-5 个即时选项
- 设计要在 10 秒内完成一次干预

#### C. 情境感知微干预
无需 GPS（性能开销大），而是基于：
- **时间段**：饭后（12:30-13:00, 18:30-19:00）、无聊时段、入睡前
- **用户自报状态**：打开页面时问"现在感觉怎么样？"
- **程序天数**：根据用户在协议中的进度调整

### 3.4 改进后的行为改变机制

| 机制 | 说明 | 科学依据 |
|-----|------|---------|
| 实施意向触发 | "如果（场景），那么（行动）"在真实时刻被唤起 | Gollwitzer 1999 |
| 微小再承诺 | 每次打开页面做一个小承诺（30秒），而非15分钟对话 | 降低执行门槛 |
| 即时替代建议 | 根据用户设定的替代方案（口香糖/茶/散步），在触发时刻推送 | 习惯替换理论 |
| 损失提醒 | 显示"你今天少抽X根/省了¥X"——实时、具体 | 损失厌恶 |
| 自我肯定 | 每次干预结尾：最低成本的自我肯定 | 自我肯定理论 |
| 社会联系 | "你儿子/女儿今晚会为你骄傲的"（在晚间时段触发） | 社会支持 |

### 3.5 具体产品结构

```
new-xinsheng/
├── index.html          # 主页面（PWA manifest + SW 注册）~2KB
├── manifest.json       # PWA 清单（使页面可添加到主屏幕）
├── sw.js               # Service Worker（离线支持 + 通知）
├── app.html            # 完整 SPA（CSS + JS + 协议全内联）~35KB
└── assets/
    └── icons/          # PWA 图标（48/72/96/144/192px）
```

### 3.6 新的每日节奏

| 时段 | 模块 | 时长 | 触发方式 |
|------|------|------|---------|
| 7:00 | **晨间签到**：今天的目标是什么？ | 30秒 | 通知/打开页面 |
| 12:00 | **午间触发检查**：现在想抽烟吗？ | 10秒 | 通知 |
| 空闲随机 | **渴求救援**：打开即用的紧急干预 | 15秒 | 主屏幕图标 |
| 18:00 | **高危提醒**：还记得你的替代计划吗？ | 10秒 | 通知 |
| 21:00 | **晚间反思**：今天做到了什么？ | 60秒 | 通知 |

### 3.7 实施优先级

1. **P0（最低可行改进）**：将主页面改造为 PWA（manifest + SW），添加离线缓存
2. **P0**：实现"紧急按钮"——主屏幕图标直接打开渴求干预（非对话）
3. **P1**：实现基于时间段的通知推送（通过 Service Worker 的 periodic sync）
4. **P1**：将每日 1 次对话拆分为 3-4 次微干预
5. **P2**：根据用户状态和程序进度个性化通知内容
6. **P3**：超个性化——根据用户之前设置的值（family/health/dignity/child）和触发器个性化每条消息

## 四、对"接下来怎么办"的回答

你说得对。当前产品的问题是：

**它创造了一个"顿悟时刻"，但没有把那个顿悟带到真实世界中去。**

接下来要做的是重构产品架构——从"每日一次对话"改为"全天持续陪伴"。每次打开页面或收到通知，都是一次 10-30 秒的微干预，但一天会重复 3-5 次。这样：

1. 洞察不仅在对话中产生，更在真实时刻被唤起
2. 用户不需要"记住"要做什么——页面会在需要时提醒他
3. 高频低强度的干预比低频高强度更有效（行为改变研究的共识）

技术上，核心改动是引入 Service Worker + 通知推送（静态站点完全可行，不需要服务器），以及将产品改造为 PWA（可添加到手机主屏幕，像原生应用一样工作）。
